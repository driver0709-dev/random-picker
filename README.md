# Случайный выбор (игра «Найди стикер»)

PWA-приложение: из списка вариантов случайно выбирает N вариантов без повторов.
Основной сценарий — игра для пары «найди стикер на теле».
Работает офлайн, все данные хранятся только на устройстве (`localStorage`).
Без сборки и зависимостей: чистые HTML, CSS и JS.

## Возможности

**Профили** (переключатель вверху экрана, выбор запоминается):

| Профиль      | Пул                                            | Размер по умолчанию |
|--------------|------------------------------------------------|---------------------|
| Парень       | общие зоны тела + пункты для парня             | 39                  |
| Девушка      | общие зоны тела + пункты для девушки           | 40                  |
| Свой список  | ваш собственный список                         | —                   |

Интимные зоны всегда участвуют в выборке, отдельного фильтра нет.

- При первом выборе «Парень» или «Девушка» спрашивается возраст (18+). Ответ «Да»
  запоминается. После ответа «Нет» доступен только «Свой список», а при следующей
  попытке открыть «Парень» или «Девушка» вопрос появится снова.
- Повторы в списке не допускаются (сравнение без учёта регистра, лишних пробелов
  и «ё/е»).

Списки «Парень» и «Девушка» в приложении не редактируются, они задаются в файле
`data/presets.js`. Общие зоны записаны там один раз (`COMMON`) и подставляются в оба
списка, а ниже идут пункты только для парня (`GUY`) и только для девушки (`GIRL`).
**Фразы.** В профилях «Парень» и «Девушка» под результатом появляется блок «Скажи»
с двумя случайными фразами для того, на ком расклеены стикеры. «Выбрать ещё раз»
обновляет и зоны, и фразы, а «Копировать» копирует и то и другое. Фразы лежат
в `PRESETS.PHRASES`. Если фраза зависит от рода, она записывается как
`{ guy: '…', girl: '…' }`: `guy` — стикеры на парне (говорит он, ищет она),
`girl` — наоборот. В «Своем списке» фразы не показываются.

Чтобы изменить списки или фразы, отредактируйте этот файл, увеличьте версию кэша
в `service-worker.js` (см. «Обновление приложения») и опубликуйте заново.

**Свой список**: добавление по одному или списком (каждый с новой строки), редактирование,
удаление, «Очистить всё» с подтверждением. Пустые строки и дубликаты пропускаются
с уведомлением.

**Выбор**: количество N из выпадающего списка (1…размер пула), последнее значение
запоминается. Используется частичная перетасовка Фишера–Йетса и `crypto.getRandomValues`
с отбраковкой, чтобы не было смещения по модулю. Результат можно выбрать заново
(«Выбрать ещё раз») или скопировать («Копировать»).

Светлая и тёмная тема, учёт выреза экрана iPhone (safe-area).

## Структура

```
index.html         разметка (основной экран, окно 18+)
style.css          стили (mobile-first, палитра «пыльная роза и нюд», светлая/тёмная тема)
app.js             логика приложения
data/presets.js    стандартные списки «Парень» и «Девушка» (GUY / GIRL)
manifest.json      манифест PWA
service-worker.js  офлайн-кэш
icons/             иконки 192×192 и 512×512
```

## Запуск локально

Service worker работает только через `http://localhost` или `https://`, поэтому
открывать `index.html` двойным кликом нельзя — нужен локальный сервер.

**Проще всего на Windows:** дважды щёлкните `start.cmd`. Откроется окно сервера и браузер
с адресом http://localhost:8080. Пока пользуетесь приложением, окно сервера не закрывайте.
Нужен установленный [Node.js](https://nodejs.org).

То же вручную из папки проекта:

```bash
node serve.js 8080 --open
```

Файлы `serve.js` и `start.cmd` нужны только для локальной проверки, на хостинг их
загружать не обязательно.

Проверка офлайна на компьютере: DevTools → Application → Service Workers → отметьте
**Offline** и перезагрузите страницу.

Открыть с телефона в той же Wi-Fi-сети можно по адресу `http://<IP-компьютера>:8080`,
но по обычному http браузер не зарегистрирует service worker и не предложит установку.
Для полноценной проверки на телефоне используйте хостинг с https (ниже).

## Бесплатное размещение на GitHub Pages

1. Создайте на GitHub публичный репозиторий, например `random-picker`.
2. Загрузите в него файлы проекта (в корень репозитория):

   ```bash
   git init
   git add .
   git commit -m "Случайный выбор: PWA"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/random-picker.git
   git push -u origin main
   ```

   Либо через веб-интерфейс: **Add file → Upload files**.
3. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch**,
   ветка `main`, папка `/ (root)` → **Save**.
4. Через 1–2 минуты приложение будет доступно по адресу
   `https://<ваш-логин>.github.io/random-picker/`.

Подойдут и другие бесплатные хостинги статики с https: Netlify, Cloudflare Pages, Vercel
(достаточно перетащить папку проекта в их веб-интерфейс).

## Установка на телефон

Сначала откройте адрес приложения и дождитесь полной загрузки: после первого открытия
файлы попадут в кэш, и дальше приложение работает без интернета.

**iPhone (Safari):** кнопка «Поделиться» → «На экран «Домой»» → «Добавить».

**Android (Chrome):** меню ⋮ → «Установить приложение» (или «Добавить на главный экран»).
Chrome может сам показать баннер с предложением установки.

## Обновление приложения

После изменения файлов увеличьте версию кэша в `service-worker.js`
(например, `const CACHE = 'random-picker-v7'`) и опубликуйте. Установленное приложение подхватит
новую версию при следующем запуске (иногда нужно открыть его дважды).

## Проверка по критериям приёмки

- 30 вариантов, N = 5 → выводится ровно 5 разных вариантов.
- «Выбрать ещё раз» даёт новый случайный набор.
- Закройте и снова откройте приложение — списки, профиль и N на месте.
- Включите режим полёта и откройте приложение с главного экрана — оно работает.
- «Парень» → в поле «В пуле» 39, никогда не выпадают пункты только из «Девушки»;
  «Девушка» → 40, никогда не выпадают пункты только из «Парня».
